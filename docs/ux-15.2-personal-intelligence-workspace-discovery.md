# UX-15.2 Discovery — Personal Intelligence Workspace

**Discovery only — no code, no migrations, no RLS changes, no AI
orchestration changes, no Knowledge Exchange changes.** Audits the
landing experience after login and every surface it competes with or
duplicates: Home, Hub, Dashboard, Workspace (as a concept), Sidebar,
Command Palette, Recent Activity, Collections, Notes, Documents,
Conversations, Knowledge Graph, and AI entry points — grounded in the
actual routes/components as they exist after UX-15.1, not assumptions.

## 1. Method

Traced the post-login path from `HomeRedirect` through every page it can
route to, read every "command center"-style page in full
(`WorkspaceIntelligenceHubPage`, `ExecutiveDashboardPage`,
`WorkspaceEvolutionPage`, `WorkspaceCollaborationPage`), read the shared
components each one renders, and read the full `Sidebar`/`NovaCommandBar`
nav surfaces. Notes/Documents/Conversations/Knowledge Exchange list
pages were already thoroughly audited in UX-15.1's own discovery
(`docs/ux-15.1-knowledge-experience-consolidation-discovery.md`) and are
referenced here rather than re-audited from scratch.

## 2. Headline findings

1. **Four separate pages all compete to be "the" intelligence overview,
   with real content overlap, not just thematic overlap.** `HomeRedirect`
   sends every workspace user to `/hub` (`WorkspaceIntelligenceHubPage`,
   174 lines, 12 stacked sections). The sidebar also links to `/dashboard`
   (`ExecutiveDashboardPage`) and `/evolution` (`WorkspaceEvolutionPage`).
   Concretely: **`/hub` and `/evolution` both render the identical
   `MaturityBadge`, `EvolutionTimelineSection`, and `ConceptEvolutionSection`
   components** against the same `useWorkspaceEvolutionReport`-shaped data
   — Hub calls them "Recent Evolution"/"Active Concepts", Evolution calls
   the same components "Knowledge Timeline"/"Concept Growth". **`/hub` and
   `/dashboard` both render the identical `RecommendedActionsSection`**
   component against the same recommendations shape — Hub calls it
   "Suggested Next Actions", Dashboard calls it "Recommended Actions". A
   user has no way to know, from the sidebar alone, that "Hub" and
   "Dashboard" and "Evolution" are three different amounts of the same
   information rather than three different things.
2. **"Recent activity" (recent notes + active conversations) is
   independently fetched and independently rendered three separate ways**
   for the same underlying data: `WorkspaceIntelligenceHubPage` renders
   `RecentNotesSection` + `ActiveConversationsSection` (two separate
   components, each its own `<ul>` of title/link/relative-time rows);
   `WorkspaceCollaborationPage` — a different page — issues its own
   independent `useNotes({limit:5})` + `useConversations()` calls and
   passes them into `CollaborationSection`, which **merges and re-sorts
   them into a third, inline-built "recent activity" feed** (`ActivityItem[]`,
   built and sorted directly in the component). Three separate
   implementations of "a list of {title, link, relative-time}" for what
   is, at the data level, the same two queries.
3. **There is no single canonical "Recent Activity" surface at all** —
   despite the task's own audit list naming it as something to review,
   grep confirms no component or page is actually titled/labeled "Recent
   Activity." It exists only as the two ad hoc, independently-built
   renderings above.
4. **The Hub page is a long, undifferentiated vertical stack, not a
   workspace.** All 12 sections (Executive Summary, 4 stat cards,
   Collaboration teaser, Recent Notes, Active Conversations, Active
   Concepts, Knowledge Gaps, Document Relationships, AI Insights, Recent
   Evolution, Suggested Next Actions, Workspace Objectives) render at the
   same visual weight, in a fixed order, with no way to tell "what needs
   my attention right now" from "background context I can skim later."
   This is the concrete shape of the task's own "feel like an operating
   system, not a dashboard" framing — today it reads as one long report.
5. **The sidebar has 11 top-level items, 4 of which are the overlapping
   intelligence-overview pages above** (`Dashboard`/`Hub`/`Collaboration`/
   `Evolution`), alongside `Library`/`Knowledge`/`Export Center` (added in
   UX-15.1)/`Notes`/`Search`/`Chat`/`Settings`. There is no grouping or
   visual hierarchy — every item is a flat, equally-weighted `NavLink`.
6. **"Workspace" has no page of its own** — the task's own audit list
   names "Workspace" as a surface to review, but no such route exists.
   "Workspace" today is a concept split across three unrelated places:
   the `WorkspaceSwitcher` (picks which workspace's data everything else
   shows), `WorkspaceCollaborationPage` at `/collaboration` (members +
   shared stats), and `WorkspaceManagementPage` at `/settings/workspaces`
   (create/rename/delete workspaces). A new user has no single place to
   answer "what is a workspace, and what's in mine."
7. **Terminology inconsistency between the two nearest-competing pages**:
   `ExecutiveDashboardPage` opens with a personalized greeting
   (`useGreeting`'s `headline`/`subtext`, e.g. "Good morning, Alex"); `Hub`
   opens with a static, impersonal label ("Workspace Intelligence Hub" /
   "Your command center for this workspace"). Both claim to be *the*
   command center, in different voices.
8. **`useCommandContext()` already resolves most of the "context
   awareness" the task's Phase 4 asks for, unused by Hub/Dashboard/
   Evolution today**: `userId`, `workspaceId`, `workspaceName`, `pathname`,
   `documentId` (from route params when present), and
   `inProgressDocument` (via the existing `getMostRecentReadingProgress`
   API, already used by `readerCommands.ts`'s `buildContinueReadingCommand`
   for the Command Bar's own "Continue reading" entry). None of the three
   overview pages surface "continue where you left off" today — that
   entry point exists only inside the Command Bar, one keystroke away
   from being invisible to anyone who doesn't know `Cmd/Ctrl+K` exists.
9. **The Command Bar (`NovaCommandBar.tsx`) still hand-rolls its own
   `<dialog>` open/close `useEffect`**, the same boilerplate UX-15.1
   consolidated into `src/shared/components/ui/Dialog.tsx` for the eight
   Import/Export dialogs — not touched by that phase because it wasn't a
   Knowledge Exchange dialog, but the identical pattern (`showModal()`/
   `close()` synced to an `open` prop) is present here too. Its own
   focus-management/keyboard-nav logic is genuinely dialog-specific and
   would stay; only the show/close mechanics are duplicated.
10. **No page reads `getMostRecentReadingProgress` except the Command
    Bar's own command builder** — "Reading Progress" (named directly in
    the task's Phase 3 card list) has real backing data
    (`reading_progress` table, `useReadingProgress.ts`,
    `documentJourney.ts`) that is fully wired into the Reader itself but
    never surfaced as a "continue reading" prompt anywhere a user would
    naturally land after logging in.

## 4. The sidebar, exactly as it exists

Confirmed by direct read of `Sidebar.tsx`'s `navItems` array — 11 items,
all linked, all flat (no grouping, no visual hierarchy, every entry a
same-weight `NavLink`):

`Dashboard`, `Hub`, `Collaboration`, `Evolution`, `Library`, `Knowledge`,
`Export Center` (added in UX-15.1), `Notes`, `Search`, `Chat`, `Settings`.

Four of those eleven (`Dashboard`/`Hub`/`Collaboration`/`Evolution`) are
all "workspace intelligence overview" surfaces with real component/data
overlap (§2.1–2.2) — a user has four separate, equally-weighted sidebar
entries before reaching a single actual content type (Library/Knowledge/
Notes/Chat).

## 5. Recommendations for Phase 2/3/4/5 (not yet implemented)

- **Phase 2 (workspace design)**: `/hub` is the natural single landing
  surface — `HomeRedirect` already sends every workspace user there.
  Recommend restructuring its 12 flat sections into a small number of
  purposeful zones answering the task's own six questions (What am I
  working on / What changed / What deserves attention / What to
  continue / What to learn / What to organize), rather than building a
  fifth new page. `/dashboard` and `/evolution`'s genuinely distinct
  content (intelligence *scores*, growth *analytics*, *forecasts*,
  *journey milestones*) can fold into Hub as an "explore more" tier
  below the primary zones, rather than staying separate, unlinked, or
  thinly-linked destinations.
- **Phase 3 (cards)**: consolidate `RecentNotesSection`/
  `ActiveConversationsSection`/`CollaborationSection`'s inline activity
  feed into one shared "recent activity" list component parameterized by
  item type, reused by both Hub and Collaboration — closing finding #2's
  three-implementations-of-one-list problem. Add a "Continue Working"
  card backed by the already-existing `getMostRecentReadingProgress`
  (finding #8) — new UI, no new data layer.
- **Phase 4 (context)**: extend `useCommandContext()` (already resolves
  workspace/user/document/in-progress-reading) rather than inventing a
  new context hook; add `collectionId`/`conversationId` the same way
  `documentId` is already derived from route params, only where a
  card's own page actually needs them.
- **Phase 5 (navigation)**: fold `Dashboard`/`Evolution` into Hub content
  (per Phase 2) rather than keeping four separate "overview" nav entries;
  `Collaboration` stays a distinct nav item (it has a real, non-overview
  job — member management — that doesn't belong on a personal workspace
  landing page). This reduces the sidebar's top-level "overview" surface
  count from four linked entries to one.

## 6. Explicitly out of scope (per the task's own constraints)

No change to `PackageVersion`/`PackageValidator`/`PackageExporter`/
`PackageImporter`, no change to Knowledge Exchange package types/export/
import/validate logic, no change to AI orchestration
(`src/modules/ai/orchestration/**`), no migrations, no RLS changes, no
new Edge Functions. Every recommendation above is presentation/routing
only: which existing hook's data a card renders, and where a page lives
in navigation — never new backend computation.
