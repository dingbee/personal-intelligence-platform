# Chapter 6: Knowledge Capture

## Purpose

Quick Capture exists for the moment you have something to save — a file, a thought, a link — and don't want to think about where it belongs first. Drop it in, and NOVA routes it to the right place automatically.

## Feature Overview

- **Quick Capture dialog** — opened from anywhere via the Command Bar, accepts a dropped file or typed text in one small panel
- **Automatic routing** — a dropped document-type file (PDF/EPUB/DOCX/etc.) goes to the Library; a dropped image goes to Images; typed text becomes a Note; a pasted URL is recognized as a link
- **Inline upload progress** — each captured item shows its own status (uploading/done/error) without leaving the dialog

## Navigation

- Open Quick Capture from the **Command Bar** (⌘K or the search icon), or its dedicated shortcut/command

## Real-World Examples

- You're mid-conversation in Chat and think of an unrelated document you need to save — open Quick Capture, drop the file, close the dialog, and keep going without navigating away from Chat.
- You have a quick thought worth keeping — open Quick Capture, type it, and it becomes a note immediately, no need to visit the Notes page first.

## Typical Workflows

1. **Capture, then organize later**: use Quick Capture to get something into the system fast, then tag/collection-assign it properly from its own detail page afterward.
2. **Multi-item capture**: drop several files of mixed types at once — each routes independently and shows its own progress.

## Best Practices

- Use Quick Capture for the "get it in the door" step, not as a substitute for organizing — a quickly-captured item still benefits from a title, tags, or a collection assignment afterward.
- Treat a captured image the same as one uploaded from the Images tab — it goes through the same derivative pipeline and is immediately available in the Image Reader and Lightbox.

## Common Mistakes

- Expecting Quick Capture to do anything beyond routing — it doesn't summarize, extract knowledge, or tag automatically; those are separate, deliberate steps elsewhere in the platform.
- Not noticing a capture failed (shown inline as an error status) and assuming it succeeded — check the dialog's per-item status before closing it if you're capturing something important.

## Related Features

- **Library & Reading** (Chapter 1) — captured documents/images land there
- **Notes** (Chapter 2) — captured text becomes a note there

## AI Capabilities

- None directly — Quick Capture's routing logic is deterministic (file type / text-vs-URL pattern matching), not AI-driven. Everything AI-related (extraction, summarization) happens afterward, in the destination module

## Limitations

- No batch tagging or collection assignment from within the capture dialog itself — that happens after, on the item's own page
