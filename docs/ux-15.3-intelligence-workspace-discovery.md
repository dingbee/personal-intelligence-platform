# UX-15.3 Discovery — Intelligence Workspace & Proactive Assistant

**Discovery only for §1–§2 — no implementation before the audit.** Audits
every source of user activity named in the task (notes, conversations,
documents, collections, reading progress, workspace activity, AI memory,
command history, recent imports, recent exports) against the real schema
and API layer, grounded in what UX-15.2's Hub already fetches
(`src/modules/hub/hubData.ts`) and what UX-11's Dashboard already
computes (`src/modules/intelligence/dashboard/dashboardInteraction.ts`).

## 1. Method

Read every already-existing signal/recommendation engine in full
(`recommendationEngine.ts`, `dashboardMetrics.ts`, `dashboardInteraction.ts`,
`graphSignals.ts`, `knowledgeGaps.ts`), the Knowledge Exchange import
path for every object type (to check for provenance/timestamp markers),
and the real schema for every table named in the task's activity list.
The goal: identify what's already computed and reusable vs. what would
require new backend infrastructure — never the latter, per the task's
own constraint.

## 2. Signal inventory — what exists, per source

| Source | Signal(s) available today | Where it already lives |
|---|---|---|
| Notes | creation/update timestamps, tags (`note_tags`, per-note only today), reference count (via `knowledge_links` where `source_type`/`target_type = 'note'`), import provenance (`generation_metadata.importedFrom`, set only by `importNotePackage`) | `notes` table, `listNotes`, `useNoteTags` |
| Conversations | creation/update timestamps, pinned/favorite flags, ownership (`user_id`) | `listConversations` (already used by Hub/Collaboration) |
| Documents | processing `status` (`uploaded`/`processing`/`ready`/`error`), `collection_id`, tags, reading progress presence | `listDocuments`, already used by Dashboard, not yet fetched by Hub |
| Collections | membership is **not a column** — it's `knowledge_links` rows with `source_type = 'knowledge_collection'`, `source_id = collection.id` (confirmed in `knowledgeCollections.ts`'s own header comment) | `listKnowledgeCollections`, `knowledge_links` |
| Reading progress | per-document scroll fraction + `updated_at`, most-recent-across-workspace lookup | `getMostRecentReadingProgress` (already powers UX-15.2's `ContinueWorkingCard`) |
| Workspace activity | member roster + status, per-workspace stats (`getWorkspaceStats`), ownership (`user_id` vs. current user) | `useWorkspaceMemberDirectory`, `OwnershipLine`/`SharingBadge` (UX-14.5) |
| AI memory | contradiction detection, unreviewed-suggestion detection | `findContradictoryMemoryPairs`, `hasUnreviewedMemory` (already used by both Dashboard and Hub) |
| Command history | **no signal exists** — commands are not logged anywhere (no table, no `localStorage`); `NovaCommandBar` only ever shows the static `featured` command list | grep confirms zero persistence layer |
| Recent imports | **partial** — Notes, Knowledge Nodes, and Knowledge Links each stamp `generation_metadata.importedFrom.importedAt` on import (confirmed in `importNotePackage.ts`/`importKnowledgeNodePackage.ts`/`importKnowledgeLinkPackage.ts`); **Documents, Assets, and Conversations import with no provenance marker at all** (their tables have no metadata JSONB column, or the importer doesn't set one) | `generation_metadata` column, 3 of 6 object types only |
| Recent exports | **no signal exists at all** — export generation is entirely client-side (`src/modules/export/exportService.ts` builds a file and triggers a browser download); nothing is written back to any table when an export happens | confirmed by reading `exportService.ts`/every `export<Type>Package` function — none perform a write |

## 3. What each activity indicates

- **Active work**: recent `updated_at` on a note/conversation/document; non-null `inProgressDocument`; a document whose `status` just changed.
- **Abandoned work**: a pinned/favorited conversation whose `updated_at` has gone stale; a document stuck in `processing`/`error` for longer than a normal processing run; a knowledge node with zero AI-generated edges (`disconnected_concept`, already detected by `graphSignals.ts`).
- **Learning**: recently-imported notes/knowledge nodes (`generation_metadata.importedFrom`), active/growing concepts (`ConceptEvolution`, already computed), reading-progress updates.
- **Organization**: untagged notes, orphaned documents (no collection, no tags), collections with zero members, information-organization score (already computed by `dashboardMetrics.ts`'s `computeIntelligenceScore`, but only fed with real data on `/dashboard` — Hub's own `hubData.ts` passes a hardcoded `100`, see its own code comment).
- **Collaboration**: another member's recent note/conversation (`user_id !== currentUserId`), workspace member count/stats.

## 4. Consolidation opportunities found (feeds Phase 4)

`dashboardInteraction.ts` and `hubData.ts` each independently compute the
exact same "does memory need review" condition —
`findContradictoryMemoryPairs(memories).length > 0 || hasUnreviewedMemory(memories)`
— as two copies of one boolean expression. `generateRecommendations` is
already the single consolidated engine for `chat`/`dashboard` scopes
(done in UX-14.1); Hub already consumes it via the `'dashboard'` scope
(confirmed in `hubData.ts`) — **Hub is not a duplicate consumer, it's
already wired**. What's genuinely missing: Command Palette, Export
Center, and Knowledge Explorer render **zero** recommendation output
today (confirmed by grep — none of the three reference
`generateRecommendations`), so "consolidate to one service" for those
three means *wiring the existing service in*, not de-duplicating
competing implementations that don't exist.

## 5. Gaps that cannot be closed without new backend work (left out of scope)

- **Command history** — no persistence exists. A "frequently used commands" card is not buildable from existing data; building one would require a new table or `localStorage` layer, which is new infrastructure. **Deferred.**
- **Recent exports / backup status** — no persistence exists. A "recently exported content" card is not buildable from existing data for the same reason. Workspace Health's "recent backup/export status" indicator is rendered as an explicit "not tracked yet" state rather than faked from an unrelated proxy. **Deferred.**
- **Recently imported Documents/Assets/Conversations** — no provenance marker exists for these three object types (only Notes/Knowledge Nodes/Knowledge Links do). The "recently imported knowledge" card is scoped to the object types that actually carry the signal.

## 6. What's buildable now, reusing only existing fetches/queries

Everything else in the task's Phase 2/3/5 lists is derivable from data
already flowing through `buildWorkspaceHubState` (or one more call to an
API function — `listDocuments`/`listKnowledgeCollections` — that already
exists and is already used elsewhere, e.g. by Dashboard) plus one new,
small, read-only bulk query mirroring `listKnowledgeNodeSourcesForNodes`'s
own pattern (a per-note-id tag lookup, for the untagged-notes count —
`note_tags` already exists, this is a bulk `.in()` variant of the
existing single-note `listTagsForNote`, not a new table).

See blueprint §35 for the concrete implementation this discovery feeds.
